# Vericore Website — Product-Led Evolution

## Goal
Evolve the public Vericore website from a synchronized product site into a clearer product-led experience while preserving the verified responsive baseline and keeping all claims grounded in the Vericore 0.7.x implementation.

## Principles
- Show before explaining.
- Preserve the Vericore 0.7.x product truth.
- Keep the responsive foundation intact.
- Prefer reusable visual primitives over page-specific hacks.
- Keep the site static and dependency-light.
- Treat accessibility, performance, and keyboard behavior as product requirements.

## Workstreams
1. Global visual system and navigation hierarchy.
2. Homepage product narrative and conversion paths.
3. Interactive demo storytelling.
4. Architecture/capability visualization.
5. Documentation and release UX.
6. Accessibility, SEO, performance, and route validation.

## Acceptance
- Existing routes continue to build and resolve.
- No unintended horizontal overflow at supported viewport widths.
- Primary CTA paths remain obvious on mobile and desktop.
- No unsupported Vericore capability is advertised.
- Keyboard/focus behavior remains usable.
- CI type-check, build, and route verification pass.
